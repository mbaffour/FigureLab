# FigureLab v3.5 — developer notes (what shipped, what was deferred, and why)

This session upgraded FigureLab toward the "v3.5" brief (UI/UX clarity, scientific
integrity, workflow clarity, export reliability) **without changing the app's
identity**: still one `figure_lab.html`, offline, privacy-preserving, no server,
no new runtime dependencies. Work was done in small, individually-tested commits
on the branch `enhancements-help-and-zenodo`.

Guiding principle (working autonomously on a 7k-line single-file app): **prefer
safe, additive changes over risky DOM restructuring.** A coherent, non-broken
improvement beats a half-finished rewrite when there's no user in the loop.

## Risk notes for whoever continues

- The per-panel gear popout is regenerated by `renderImgList()`; rely on the global
  `body.simple-mode .adv` CSS rule rather than gating per-panel logic on visibility.
- Never `.adv`-hide `#render-btn`, `#export-dpi`, the primary format buttons, or the
  Select annotation tool — other flows depend on them being reachable.
- CVD and any future "view filters" must stay on the DOM (`#canvas-container` CSS
  filter) and never touch `#fig-canvas`'s pixel buffer — exports and quantification
  read that buffer directly.

## v3.5 addendum — creative pass (on-device AI + What's New + research)

**Also shipped after the initial v3.5 cut:**
- **On-device AI caption polish** (`aiPolishCaption`) — uses Chrome's built-in **Prompt API (Gemini Nano)** via the global `LanguageModel`. Feature-detected (`typeof LanguageModel`), availability-checked, and guarded against echo/degenerate responses so it never clobbers the good rule-based caption. 100% on-device — nothing uploaded. Falls back silently when unsupported.
- **"What's New"** Help tab + a "new" dot on the header ❔ (shown when `localStorage['fl-seen-version'] !== APP_VERSION`, cleared on open; first-run visitors aren't nagged). Command-palette entries for both.
- Docs refreshed with a **dated** What's New: in-app tab, README changelog (`### v3.5 — 8 July 2026`), and the blog (`index.html` `#whats-new`, hero badge → v3.5).

**Tests:** now 25 passing (added AI-caption fallback + What's New coverage).

### On-device AI: "Google AI Edge" feasibility (answering the product question)
- **Chosen:** Chrome **built-in Prompt API / Gemini Nano** (`LanguageModel.availability()` → `create()` → `session.prompt()`). Runs on-device, no key, no network, **zero bundled dependencies** — a clean fit for a single-file offline app. Docs: https://developer.chrome.com/docs/ai/prompt-api
- **Not used (but viable as an opt-in bundle):** **Google AI Edge / MediaPipe LLM Inference** (or Transformers.js) can run Gemma/other open models in-browser via a WASM runtime, but requires bundling a multi-MB runtime + model weights — this breaks the "one HTML file, no dependencies" identity, so it was deliberately avoided for the core app.
- **Future idea:** the Prompt API supports **image input** (`{type:'image', value: blob}`), so a future version could draft a caption from the *actual panel pixels*, not just notes. Kept text-only for now for reliability/determinism.

### Research-informed roadmap (from `scratchpad/competitor_research.md`)
A background research pass compared FigureLab against FigureJ, ScientiFig/EzFig, QuickFigures, OMERO.figure, Inkscape/Illustrator, BioRender, napari, and others. Status of the highest-value additions it surfaced:

| Idea | Value | Size | Status |
|---|---|---|---|
| **Editable PowerPoint (.pptx) export** | Labs finalize in PPT (universal competitor feature) | M | ✅ **Shipped** — `exportPPTX()`; per-panel movable pictures + editable title; OOXML on the ZIP writer |
| **Submission package (ZIP)** | Bundle every artifact + provenance in one archive | M | ✅ **Shipped** — `exportSubmissionPackage()`; the distinctive integrity surface no competitor packages cleanly |
| **Smart import: channel detection + natural sort** | Auto-recognise DAPI/GFP/… and order panels | S–M | ✅ **Shipped** — card metadata, `_detectChannel`, `sortImagesByName`, `autoDetectChannels` |
| **One-click split-channel row** | Auto-emit aligned single-channel + merge panels — the #1 QuickFigures time-saver | M | ⏳ Next |
| **Linked / "matched" panels** | Apply B/C/gamma/LUT/zoom identically across a comparison group (OMERO.figure's signature; also an integrity safeguard) | M | ⏳ Next |
| **Align & distribute + smart guides/snapping** | Illustrator-grade alignment in freeform mode | M | ⏳ (freeform already has some align/distribute) |
| **Gel/blot splice-marker tool** | Visible journal-mandated splice divider + metadata log — cheap integrity win | S | ⏳ Next |
| **Manuscript-wide "house style" presets** | Save a style and enforce uniform fonts/labels/colors across every figure | M | ⏳ (overlaps the existing template system) |

Implementation notes for the shipped items:
- **ZIP writer** (`_zipMake`, store method, reuses `crc32`) is the shared enabler for the package and PPTX. Verified: valid central directory, stored bytes intact, all PPTX XML parts well-formed.
- The submission package captures each artifact by **temporarily intercepting `dl()`/`toast()`** and fetching the exporter's blob — so no existing exporter was refactored and the package matches the individual exports exactly.
- ⚠ **PPTX caveat:** validated structurally (valid zip + well-formed OOXML), but not opened in desktop PowerPoint from this environment — worth a manual open to confirm before relying on it.

Deliberately *not* recommended: a BioRender-style icon library (offline-hostile) and live OMERO/dataset binding (needs a server). FigureLab's differentiator remains **integrity + reproducibility for raw-data panels**.
